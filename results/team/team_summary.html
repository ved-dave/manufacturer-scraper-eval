Product-catalog scraping: what we tested, what we found, what's next

Goal: a scraping workflow that is 97% accurate and works for any manufacturer. All scores are % agreement with hand-checked answer keys.

How we measured

  • Answer keys for 4 manufacturers (Bray, Crane, Cimberio, Sioux Chief). Each key is the complete list of the site's product families, plus about 15 families checked by hand in detail: documents, CAD, images, specs and sizes. A second, independent check was done on each key.
  • Dixon and Apollo block automated access, so they have no key.
  • We compared a new processing step, which sorts the old agent's existing link lists, with the current scraper.

Main findings

  • The old agent's link list is nearly complete: it holds 98–100% of the answer-key families, documents, CAD and images on Bray, Crane and Sioux Chief. Cimberio is the exception: its list misses about half the main documents and the price list.
  • Points are lost when the list is sorted, not when it's collected. Fixed rules throw out real product pages, part numbers aren't grouped into families, and specs are read badly.

What we learned

  • When the signals disagree, flag the page as unsure; don't drop it. Fixed thresholds tuned on one site break on the next.
  • Every manufacturer already publishes its own family structure: family pages (Bray, Crane), category cards (Sioux Chief) or size tables. We should read that structure, not rebuild it from part numbers. On Sioux Chief, the category pages already in the old agent's list link to 99% of the answer key's part-number pages.
  • The AI helps most when it reads specs and backs each value with a word-for-word quote, not when it makes yes/no grouping calls. Each "same family?" answer can merge at most two families, and most duplicates never become a question.

Plan to reach 97% across manufacturers

  • 1. Site profile (2–3 days). For each new site, work out automatically how it defines a family, and save that as readable data. Grouping then follows the site's own catalog. No new code per site.
  • 2. Small additions to the old agent (their side). For each link, also save the page it was found on, a copy of the page, and a fingerprint of each file. This fixes which documents belong to which family, covers sites that block us, and avoids re-downloading.
  • 3. Specs (about 1 week). A shared dictionary of spec names, plus AI reading of spec tables and PDFs, with every value backed by a quote.
  • 4. Prove it on new sites (about 1 session per key). Answer keys for 3–5 manufacturers we have never tuned on, then a blind run with no changes. That is the real test of "works for any manufacturer".
